# 좌측 음성 선택기와 중앙 마이크 동작 연결 설계

## 문제

좌측 `VOICE / 대화 설정`에는 `OpenAI Realtime`과 `브라우저 음성` 선택기가 있지만, 중앙 입력창의 마이크 버튼은 이 선택값을 읽지 않고 항상 `useInputDictation` 받아쓰기만 실행한다. 그래서 사용자는 Realtime 음성 모델을 시작할지 로컬 음성 입력을 시작할지 화면에서 구분해 실행할 수 없다.

## 목표 동작

좌측 음성 선택기를 중앙 마이크 버튼의 단일 실행 기준으로 사용한다.

| 좌측 선택값 | 중앙 마이크 클릭 | 입력과 응답 |
| --- | --- | --- |
| `OpenAI Realtime` | Realtime 음성 세션 시작 또는 종료 | 음성을 OpenAI Realtime에 전달하고 음성으로 응답 |
| `브라우저 음성` | 브라우저 로컬 받아쓰기 시작 또는 종료 | 인식한 문장을 입력창에 채움. 자동 전송하지 않음 |

기존 텍스트 입력과 보내기 버튼은 그대로 유지한다. 기존 터빈의 `AI 음성 대화` 명령도 현재처럼 좌측 선택값을 따르며, 이번 변경은 중앙 마이크를 사용자가 선택한 방식과 일치시키는 데 집중한다.

## 화면 표시

- 선택기는 현재 위치와 저장 방식을 유지한다.
- 중앙 마이크의 접근성 이름과 도움말은 선택값에 따라 바뀐다.
  - Realtime 대기: `OpenAI Realtime 대화 시작`
  - Realtime 연결 중: `OpenAI Realtime 대화 종료`
  - 브라우저 대기: `로컬 음성입력 시작`
  - 브라우저 입력 중: `로컬 음성입력 종료`
- 마이크의 `aria-pressed`는 현재 선택된 기능의 실제 활성 상태를 나타낸다.
- 설정을 불러오거나 저장하거나 음성 세션을 종료하는 동안에는 마이크를 비활성화한다. 시작 중에는 같은 버튼으로 연결을 취소할 수 있다.
- Realtime이 선택됐지만 API 키 등으로 사용할 수 없으면 마이크를 비활성화하고 AI 설정에서 키를 확인하라는 도움말을 표시한다.
- 브라우저 받아쓰기 오류는 현재처럼 입력 도구 옆에 표시한다. Realtime 오류는 기존 대화 설정 오류 영역에 표시한다.

## 상태와 제어 흐름

`JarvisMain`이 `voice.voiceMode`를 읽어 현재 마이크 동작을 결정한다. 표시된 모드와 실행된 모드가 달라지지 않도록 `useJarvisVoice`는 기존의 선택 모드용 `start()`와 별도로 의미가 고정된 `startRealtime()`을 제공한다.

1. `JarvisMain`으로 `useInputDictation`을 옮겨 Realtime 세션과 받아쓰기 상태를 한곳에서 조정한다.
2. `voiceMode === 'realtime'`이면 마이크가 `voice.startRealtime()`과 `voice.stop()`을 호출한다. `startRealtime()`은 서버에서 확인한 선택 모드·설정·Realtime 사용 가능 상태가 모두 일치할 때만 연결하며, 불일치하면 브라우저 음성으로 대체 실행하지 않고 오류를 표시한다.
3. `voiceMode === 'browser'`이면 마이크가 `dictation.toggle()`을 호출한다.
4. `useJarvisVoice`는 `idle | starting | active | stopping` 연결 전이와 세션 소유 ref를 관리한다. 시작을 요청하는 즉시 소유권을 예약해 빠른 연속 클릭으로 세션이 두 개 생성되지 않게 한다.
5. `useInputDictation`은 외부에서 즉시 호출할 수 있는 안정된 `stop()`을 반환한다. `JarvisMain`은 이 함수를 `useJarvisVoice`의 음성 입력 중단 등록부에 연결한다. 등록 API는 cleanup 함수를 반환하며, cleanup은 자신이 등록한 함수가 아직 현재 등록일 때만 제거한다. 따라서 화면 재마운트와 등록 교체 때 오래된 cleanup이 새 등록을 지우지 않는다.
6. 중앙 Realtime 시작, 터빈 `AI 음성 대화`를 포함한 모든 `useJarvisVoice` 시작 진입점은 새 세션을 열기 전에 등록된 받아쓰기를 먼저 동기적으로 중단한다.
7. 좌측 선택기와 화면 명령의 음성 모드 변경은 하나의 `setVoiceMode()` 경로를 사용한다. 이 경로는 받아쓰기와 현재 Realtime/브라우저 AI 음성 세션을 모두 종료한 뒤 설정을 저장한다. 따라서 저장된 선택값과 현재 마이크 소유자가 다른 상태를 허용하지 않는다.
8. 받아쓰기 중에도 사용자는 좌측 모드를 바꿀 수 있다. 선택기 클릭은 먼저 현재 마이크 소유자를 중단하고, 저장 중에는 모든 음성 시작을 잠근다.
9. 설정 PATCH 응답의 저장값은 즉시 화면 상태에 반영하되 `확인 중`으로 표시하고 마이크를 잠근다. 후속 조회가 성공해야 실행을 다시 허용한다. 요청 세대 번호를 사용해 이전 조회 응답이 최신 선택값을 덮지 못하게 한다. PATCH 또는 후속 조회가 실패하면 오류와 `설정 확인 필요` 상태를 표시하고, 최신 서버 조회가 성공할 때까지 마이크 실행을 허용하지 않는다.
10. 브라우저 모드에서 터빈이 시작한 AI 음성 대화가 이미 활성 상태라면 중앙 마이크는 `브라우저 AI 대화 종료`로 표시하고 `voice.stop()`만 실행한다. 종료가 끝나고 다음에 누를 때 로컬 받아쓰기를 시작한다. 중앙 받아쓰기 시작 경로는 다른 음성 세션이 없을 때만 실행된다.
11. `JarvisChatTools`는 카메라·첨부 UI와 전달받은 마이크 상태를 표시하는 컴포넌트로 단순화한다. 음성 모드의 정책은 갖지 않는다.

이 흐름은 Realtime, 터빈의 브라우저 음성 대화, 중앙의 브라우저 받아쓰기가 동시에 마이크를 여는 상태를 막고, 화면에 표시된 선택값과 실제 실행값이 달라지는 것을 방지한다.

## 표시 상태 결정표

| 상태 | 버튼 표시 | 비활성 |
| --- | --- | --- |
| 설정 조회 전 또는 `voiceMode === null` | `음성 설정 확인 중` | 예 |
| 설정 저장 중 | `음성 설정 저장 중` | 예 |
| 저장 후 확인 실패 또는 마이크 소유자 불일치 | `음성 설정 확인 필요` | 예 |
| Realtime 선택, 사용 불가 | `OpenAI Realtime 사용 불가` | 예 |
| Realtime 시작 중 | `OpenAI Realtime 연결 취소` | 아니요 |
| Realtime 종료 중 | `OpenAI Realtime 종료 중` | 예 |
| Realtime 대기/활성 | `OpenAI Realtime 대화 시작/종료` | 아니요 |
| 브라우저 AI 대화 활성 | `브라우저 AI 대화 종료` | 아니요 |
| 브라우저 대기/받아쓰기 중 | `로컬 음성입력 시작/종료` | 아니요 |

브라우저 음성 인식 지원 여부는 첫 사용 전 브라우저 객체로 판단한다. 미지원이면 버튼을 비활성화하고 `이 브라우저는 로컬 음성입력을 지원하지 않습니다`를 표시한다. 여러 조건이 겹치면 설정 조회, 저장 또는 확인 필요, 마이크 소유자 불일치, 사용 불가, 연결 전이 순서로 도움말을 결정한다.

좌측 `SESSION / CONNECTIONS`의 `음성 입력`과 중앙 상태에는 Realtime 세션뿐 아니라 받아쓰기 활성 상태도 반영한다. 좌측 안내에는 중앙 마이크의 브라우저 모드는 입력창만 채우고, 터빈의 `AI 음성 대화`는 브라우저 인식·텍스트 모델·브라우저 합성을 이어서 실행한다는 차이를 명시한다.

## 변경 대상

- `src/cinema/JarvisMain.tsx`: 선택값에 따른 마이크 동작, 받아쓰기 상태, 상호 배제 연결
- `src/cinema/JarvisChatTools.tsx`: 모드별 마이크 표시와 전달받은 실행 함수 사용
- `src/cinema/useInputDictation.ts`: 필요하면 외부 중단 함수를 반환해 모드 전환 시 즉시 정리
- `src/cinema/useJarvisVoice.ts`: Realtime 전용 시작, 연결 전이, 외부 음성 입력 중단 등록
- 모드별 버튼 상태를 계산하는 순수 함수: 표시와 실행 결정을 표 기반으로 검증
- 관련 단위 테스트: 모드별 실행 함수, 비활성 조건, 접근성 문구 검증
- `DESIGN.md`: 좌측 선택기가 중앙 마이크의 실행 기준이라는 화면 규칙 기록

## 검증

1. 단위 테스트에서 Realtime 선택 시 `voice.startRealtime/stop`만 호출되는지 확인한다. 런타임 조건이 불일치할 때 브라우저 대화로 대체되지 않는 것도 확인한다.
2. 단위 테스트에서 브라우저 선택 시 받아쓰기만 토글되고 자동 전송되지 않는지 확인한다.
3. 순수 버튼 상태 결정 함수의 표 기반 테스트로 선택값 로딩·저장 중, Realtime 미사용 상태, 연결 전이, 각 기능 활성 상태의 문구와 비활성 조건을 확인한다.
4. 빠른 이중 클릭, 중앙 버튼으로 시작 또는 권한 요청 중 취소, 종료 직후 재시작, 받아쓰기 중 좌측 또는 화면 명령 모드 변경, 받아쓰기 중 터빈 대화 시작을 검증한다.
5. 터빈의 브라우저 AI 대화 중 중앙 버튼을 누르면 기존 대화만 종료되고 받아쓰기는 시작되지 않으며, 종료 후 다음 클릭에서 받아쓰기가 시작되는지 검증한다.
6. 설정 저장 성공·실패·재조회 실패, 오래된 조회 응답 폐기와 화면 숨김·언마운트 시 마이크 정리를 검증한다.
7. 외부 받아쓰기 중단 함수의 등록 없음, 재등록, 이전 cleanup 실행 시 현재 등록 유지 사례를 검증한다.
8. 받아쓰기 결과가 `voice.ask`를 호출하지 않는다는 부정 검증을 포함한다.
9. `npm run typecheck`와 `npm run test:unit`을 실행한다.
10. 개발 화면에서 두 선택값을 번갈아 저장하고 중앙 마이크의 도움말·상태가 즉시 바뀌는지 확인한다.
11. 실제 마이크 권한이 허용된 브라우저에서 브라우저 모드는 입력창만 채우고, Realtime 모드는 세션 상태가 켜지는지 확인한다.

## 완료 기준

- 좌측 선택값과 중앙 마이크의 실행 기능이 항상 일치한다.
- Realtime과 로컬 받아쓰기가 동시에 활성화되지 않는다.
- 사용자가 버튼 문구와 활성 표시만 보고도 현재 실행 방식을 알 수 있다.
- 브라우저 받아쓰기는 사용자의 명시적인 보내기 전에는 질문을 전송하지 않는다.
