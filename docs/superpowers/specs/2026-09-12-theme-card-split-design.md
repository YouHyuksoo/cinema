# 연출 설정 테마 카드 분리 설계

## 목표

메인 화면 왼쪽 스크롤의 단일 `SCENE / 연출 설정` 카드에서 시각 테마 관련 설정을 분리해 독립된 `THEME / 테마` 카드로 표시한다. 설정 동작과 저장 형식은 유지한다.

## 카드 구성

### THEME / 테마

- 색상 테마
- 중앙 배경
- 화면 질감
- 질감 강도

### SCENE / 연출 설정

- 운영자 영상 설정
- 메뉴 펼침 방식
- 현재 장면의 설비·차트 표현 설정
- 재생 방식, 재생 속도, 재생·일시정지·처음부터 제어

두 카드는 왼쪽 스트림에서 각각 독립된 HUD 카드와 접기·펼치기 영역을 갖는다. `THEME / 테마`를 먼저 배치하고 그 아래에 `SCENE / 연출 설정`을 둔다.

## 컴포넌트 구조

- `FilmControls`의 테마 그룹과 연출 그룹을 명시적인 하위 컴포넌트로 나눈다.
- 전체 설정이 필요한 하단 도크와 설정 대화상자는 두 그룹을 순서대로 함께 렌더링한다.
- 메인 화면의 `JarvisMain`은 두 설정 슬롯을 각각 별도 스트림 카드로 감싼다.
- `SignalFilm`은 동일한 `player`와 `camera`를 두 그룹에 전달하므로 상태 복제나 별도 저장소를 만들지 않는다.

## 동작과 접근성

- 기존 색상·중앙 배경·질감 선택 이벤트와 재생·카메라 이벤트를 그대로 사용한다.
- 카드의 `aria-label`과 summary 제목을 `테마 설정`, `연출 설정`으로 구분한다.
- 좁은 화면에서는 현재 스트림 카드의 세로 폼 규칙을 두 카드에 동일하게 적용한다.
- 카드 분리는 설정값, 재생 위치, 카메라 상태를 초기화하지 않는다.

## 검증

- 서버 렌더 마크업에서 왼쪽 스트림에 테마 카드와 연출 카드가 각각 한 번 존재하는지 검사한다.
- 테마 카드에는 색상·중앙 배경·화면 질감·질감 강도만, 연출 카드에는 재생·카메라·메뉴 설정이 들어가는지 검사한다.
- 하단 설정 대화상자와 도크가 두 그룹을 계속 모두 포함하는지 확인한다.
- `npm run typecheck`, 관련 단위 테스트, `npm run build`를 실행한다.
- 개발 화면에서 데스크톱과 모바일 카드 순서·접힘·스크롤을 확인한다.

## 문서 영향

`DESIGN.md`의 메인 화면 연출 설정 규칙을 두 카드 구성으로 갱신한다.
