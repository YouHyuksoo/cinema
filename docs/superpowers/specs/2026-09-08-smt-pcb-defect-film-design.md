# SMT PCB 불량 분석 연출과 자동차 선택 옵션

## 승인된 방향과 목적

2026-09-08 사용자 요청: 기존 `투명 설비 분석(machine)` 연출을 SMT 공정의 PCB 불량 부품을 보여주는 연출로 바꾸고 자동차는 옵션으로 보존한다. 사용자는 3D PCB 전체 스캔 → 불량 부품 접근·확대 → 부품번호·불량 유형·검사 공정 표시 → 전체 복귀 구성을 승인했다.

기본 장면은 PCB다. 기존 자동차 그림을 PCB 사진으로 교체하는 것이 아니라, 보드와 부품을 데이터에 따라 개별 도형으로 그린다. 이 문서는 구현 전 검토 명세이며 아직 구현 완료를 의미하지 않는다.

## 현재 소스와 보존 범위

- `filmProgram.ts`의 `machine`은 36초 자동차 장면이다. 메뉴 ID·순서·개수·36초 길이를 유지해 전체 538초 재생과 저장된 장면 참조를 보존한다.
- `drawTransparentMachineFilm.ts`는 현재 자동차만 그린다. 기존 자동차 구현은 별도 자동차 렌더러로 보존하고 PCB/자동차를 분기하는 얇은 진입점을 둔다.
- `raceCar.ts`, `components/drawRaceCar.ts`, `components/drawRaceDiagnostics.ts`의 자동차 모델·값·시간 연출은 변경하지 않는다.
- 기존 휴대폰 기판의 IC·수동소자 표현과 `holoSpace.ts`의 투영을 참고·재사용한다. 배터리 구멍이 있는 휴대폰 보드 형태와 고정 배치는 SMT 기판으로 재사용하지 않는다. 기존 휴대폰 연출도 회귀 없이 보존한다.
- `productInspection.ts`의 치수 공차 판정은 범주형 SMT 불량 판정과 다르므로 새 불량 데이터를 그 모델에 억지로 넣지 않는다.
- 현재 실시간 피드에는 PCB 부품 좌표·부품별 불량 계약이 없다. DB 연결이나 실제 검사 판정 연동을 완료했다고 표시하지 않는다.

## 화면과 연출

### 기본 PCB 표현

- 모델명·시리얼을 가진 시연용 직사각형 SMT PCB 한 장을 큰 사선 3D 시점으로 표시한다.
- 기판 두께, 동박 배선, 비아, 패드, IC·저항·커패시터·커넥터 등의 개별 부품이 읽히도록 구성한다. 모든 부품은 같은 좌표계와 투영을 사용한다.
- 정상 부품은 낮은 명도의 반투명 표현, 불량 부품은 높은 대비의 강조색·타깃 윤곽·불량명으로 구별한다. 색만으로 판정을 전달하지 않는다.
- 시연 불량은 기존 프로젝트 용어와 맞춘 `납량 부족(SPI)`, `부품 위치 편차(MAOI)`, `납땜 브리지(AOI)` 세 종류를 사용한다. 실제 공정 판정을 재계산하지 않고 전달된 판정을 시각화한다.
- 불량 종류에 맞는 시연 도형을 사용한다. 납량 부족은 패드 접합부, 위치 편차는 기준 패드와 부품의 어긋남, 브리지는 인접 단자 사이 연결부를 확대한다. 실제 AOI 이미지나 실제 결함 단면처럼 주장하지 않는다.
- 화면에 `SMT PCB 검사 시연`을 표시한다. 실데이터가 주입되면 장면 문서의 출처·시각을 표시하고, 기판 형상과 검사 영상이 실제 CAD/영상에서 유래한 것처럼 표시하지 않는다.

### 36초 시퀀스

1. 0~4초: PCB 전체 등장, 표면 스캔, 불량 위치 표시.
2. 4~28초: 불량 부품 배열을 순서대로 순회한다. 이 구간을 실제 불량 개수로 나누고 각 구간에서 접근 → 확대 유지·정보 판독 → 후퇴를 수행한다. 예제는 세 부품이다.
3. 28~34.5초: 전체 보드로 복귀하고 검사 대상·정상·불량·미검사 수와 불량 목록을 표시한다.
4. 34.5~36초: 기존 장면 전환 규칙에 맞춰 마무리한다.

카메라는 단순 테두리 강조가 아니라 대상 부품으로 실제 투영 중심과 거리/배율을 보간한다. 부품·패드·타깃·연결선은 동일한 카메라 계산을 사용한다. 큰 확대 화면의 정보창에는 참조번호, 부품명, 불량 유형, 판정 공정이 표시된다. 임의의 불량 확률·실측값·수리 지시는 추가하지 않는다.

불량이 없으면 전체 스캔과 정상/미검사 집계로 유지하고 존재하지 않는 불량 부품을 생성하지 않는다. 전달된 값과 판정은 시간에 따라 바뀌지 않으며, 동일 시간으로 탐색하면 동일한 화면을 재현한다.

### 반응형과 기존 동작

- PC는 큰 중앙 보드와 측면 판독 영역을 사용한다. 좁은 세로 화면은 보드와 판독 영역을 위아래로 재배치해 전체 PC 화면을 작게 축소하지 않는다.
- 가로/세로 모두 실제 도크 예약 높이를 반영한다. 구체 메뉴의 초기 닫힘·우하단 축소·드래그는 변경하지 않는다.
- 기존 클릭 일시정지, 재생 속도, 현재 장면 반복, 전체 연속, 시간 탐색을 유지한다.
- 부품 수동 선택·보드 직접 회전은 이번 범위에 추가하지 않는다. 화면 클릭은 기존 재생/정지 동작을 유지한다.
- 기존 테마·폰트·패널·타깃 표현을 사용한다. 새 라이브러리나 이미지 생성 API는 추가하지 않는다.

## PCB / 자동차 옵션

- 메뉴의 표시 이름은 `PCB 불량 분석`, 부제는 PCB 검사 주제로 바꾸며 `machine` ID를 유지한다. 설정에서 자동차도 선택 가능함을 안내한다.
- 해당 장면의 `연출 설정`에 `분석 대상` 선택을 추가한다: `PCB 불량 분석 (기본)` / `자동차`.
- 최초 진입·새로고침은 PCB다. 선택값은 이번 페이지 세션에서 장면 이동·재개방 중 유지한다. 영구 저장은 하지 않는다.
- 대상 변경 시 현재 `machine` 장면의 시작 시점으로 이동하되 재생/일시정지 여부·속도·테마·질감·반복 방식은 유지한다. 다른 장면으로 잘못 이동하지 않는다.
- 자동차 선택은 기존 36초 자동차 연출을 그대로 재생한다. 화면 및 설정의 대상 표기가 선택과 일치해야 한다.
- PCB/기판/투명 설비 장면 호출 문구와 기존 자동차 관련 설명·별칭을 점검한다. 명시적인 자동차 요청을 PCB 실행 성공으로 응답하지 않는다. 기존 명령 경로에 분석 대상 선택을 전달할 수 있으면 전달하고, 전달하지 못하는 경로는 대상 선택이 필요함을 명확히 안내한다. 새로운 음성 연결이나 음성 기능 자체는 만들지 않는다.

## 부품 데이터와 변경 규칙

- `machine` 장면의 PCB 데이터는 기존 `scene-data-contract.md` 봉투와 저장소를 통해 전체 교체 및 부품 ID별 패치를 지원한다. 자동차 시연 데이터는 별도 보존한다.
- 보드 정보: 모델명, 시리얼, 가로·세로·두께(숫자, mm). 보드 문맥 안의 참조번호(`U1`, `R12` 등)를 부품의 자연키 `id`로 쓰고 표시명 `label`을 별도로 둔다.
- 부품은 배열이며 부품번호/패키지 종류, 보드 내 위치·회전·크기, 검사 공정, 불량 코드로 구성한다. 보드 표면 한 면의 부품을 이번 범위로 한다. 단위 없는 문자열 좌표나 무작위 런타임 ID를 사용하지 않는다.
- 패키지·검사 공정·불량은 공유 enum/서술자로 정의한다. 기본 불량 코드는 정상, 미검사, 납량 부족, 위치 편차, 납땜 브리지이며 표시는 한 곳의 코드-라벨 매핑을 사용한다.
- 부품 ID와 label은 부분 패치로 변경하지 않는다. 추가·삭제·위치/형상 변경은 전체 문서 교체, 기존 부품의 불량 코드·검사 공정은 서술자가 허용하는 ID별 패치로 처리한다.
- 정상·불량·미검사 수와 자동 순회 대상은 동일한 부품 배열에서 파생한다. 부품 개수나 세 불량 참조번호를 렌더러에 하드코딩하지 않는다.
- 빈 부품 배열은 대상 없음, 잘못된 enum·중복 ID·유효하지 않은 치수·기판 밖 좌표는 이유가 있는 데이터 오류로 처리한다. 잘못된 문서/패치는 기존 정상 상태를 부분적으로 덮어쓰지 않는다.
- 실제 Oracle 소스 연결, 관리자 매핑 기능 확장, 실제 AOI/SPI 이미지 취득, CAD/Gerber 가져오기는 이번 범위 밖이다. UI 시연을 위해 새 DB 데이터나 실제 불량 판정을 만들지 않는다.

## 책임 분리와 영향 경로

| 책임 | 대상 경로 |
|---|---|
| PCB 모델·시연 데이터·코드·검증·시간 상태 | 새 PCB 전용 순수 모듈, 부품 서술자 |
| 카메라·투영·PC/모바일 배치 | PCB 투영/레이아웃 모듈, 기존 `holoSpace.ts` 활용 |
| 기판·부품·불량 형상·판독창 | `components/`의 PCB 전용 그리기 부품 |
| PCB 화면 조립 및 자동차 분기 | 새 PCB/자동차 렌더러, 얇은 `drawTransparentMachineFilm.ts` |
| 분석 대상 상태와 선택 UI | `useFilmPlayback.ts` → 전용 설정 컴포넌트 → `FilmControls.tsx` |
| 재생 호출·메뉴·아이콘 | `drawSignalFilm.ts`, `filmProgram.ts`, `FilmChapterIcon.tsx`, `FilmChapterMenu.tsx` |
| 데이터 전체 교체·부분 변경 | `filmSceneData.ts` → `sceneDataRegistry.ts` / `sceneFields.ts` → `sceneDataStore.ts` |
| 기존 명령/설명과의 정합 | `hatcheryTargets.ts`, `jarvisCommands.ts` 및 관련 호출부 |
| 프로젝트 시각 규칙·계약 문서 | `DESIGN.md`, `docs/standards/scene-data-contract.md` |

`src/app`은 그대로 조립 진입점으로 유지한다. 기존 서버와 3000 포트를 보존하며 원본 HUD 디렉터리나 다른 작업 파일은 변경하지 않는다.

## 검증과 완료 조건

- 데이터: 기본 시연·전체 교체·ID 패치, 정상/불량/미검사 집계, 0/1/복수 불량, 중복 ID·비정상 수치·잘못된 코드 거부.
- 시퀀스: 모든 불량 순회, 접근/판독/후퇴, 되감기 결정성, 불량 없음, 대상 변경 후 시작점과 정지 상태 보존.
- 렌더러: 실제 보드/부품/타깃 투영 정합, Canvas save/restore 및 다음 장면 오염 방지, 모바일 경계.
- 회귀: 기존 자동차 도형·시연값·36초, 총 538초·16개 메뉴, 자동차 옵션, 기존 화면 클릭 일시정지와 메뉴 구체.
- 실제 브라우저: PCB 기본 진입, 세 시연 불량의 확대 형상/라벨, 모바일 세로, 설정 자동차 전환과 PCB 복귀, 재생/정지/탐색 확인. 마이크·카메라·실제 AI 연결은 시작하지 않는다.
- 명령: `npm run typecheck`, `npm run test:unit`, `npm run build`, `npm run lint`, `git diff --check`.
- 실제 검사 데이터 연동과 물리 휴대폰 터치는 수행 여부를 따로 보고하며, 자동 테스트만으로 검증했다고 주장하지 않는다.
