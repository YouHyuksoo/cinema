# 부유하는 육각 구체 메뉴

작성일: 2026-09-08
상태: 초기 구현 검토 완료. 실화면 사용자 피드백에 따라 큰 전면 부유 구체와 드래그 이동으로 변경한다.

## 목적과 승인된 방향

메인 화면에서도 하단 링 메뉴를 축소할 수 있게 한다. 축소된 메뉴는 기존 사각 앵커 대신, 기존 메뉴 아이콘을 담은 육각형 조각들이 구 표면을 감싸는 큰 전면 입체 객체로 표시한다. 축구공을 연상시키되 육각형 사이에 틈이 있는 홀로그램 구체다. 구체를 밀어 화면 안에서 이동하고, 짧은 클릭은 메뉴를 펼치는 동작이며 장면 선택은 펼쳐진 기존 링에서만 한다.

평면 이미지 방식은 앞뒤 깊이 표현이 제한적이다. 별도 WebGL 엔진을 추가하는 방식은 이번 메뉴 변경에 비해 의존성과 렌더링 복잡도가 크다. 기존 React/SVG 아이콘과 CSS 3D 변환을 재사용하는 입체 조각 방식으로 진행한다.

## 시각 구성

- 모든 `FILM_CHAPTERS` 항목을 ID 기준으로 한 번씩 구체의 육각 조각에 대응시킨다. 목록과 아이콘을 별도 하드코딩하지 않는다.
- 조각 중심은 구 표면에 고르게 분포하고 각 면은 바깥쪽을 향한다. 면 크기는 인접 면이 겹치지 않고 구체 정면에서 작은 틈이 읽히도록 설정한다. 닫힌 다면체의 정확한 축구공 위상이나 오각형 구성은 요구하지 않는다.
- 기존 시안 계열 테마·육각 프레임·`FilmChapterIcon`을 사용한다. 뒤쪽 면은 앞쪽 면보다 어둡게 처리하거나 뒷면을 숨겨 입체 깊이를 표현한다. 메뉴 이름은 축소 상태에서 생략하고 아래에 작은 '메뉴 펼치기' 안내를 둔다.
- 구체는 화면 앞쪽에 크게 떠 있으며 마우스/터치 드래그로 위치를 옮긴다. 놓으면 짧고 감쇠하는 관성 이동 후 그 위치에서 약 4px 부유와 30초 주기 회전을 계속한다. 화면 경계 안으로 제한하며, 이동 위치는 다음 축소 전까지 유지한다. 매번 축소하면 오른쪽 하단 구석으로 이동한다.
- 기준 구체 지름은 데스크톱 240px, 너비 680px 이하 180px, 높이 500px 이하 132px로 구현 시작한다. 짧은 높이가 우선하며 작은 화면에서는 경계에 맞춰 제한한다. 닫힌 메뉴는 전면 오버레이이므로 하단에는 32px와 safe-area 추가분만 예약한다. 초기 위치도 오른쪽 하단이며 사용자가 자유롭게 옮길 수 있다. 가장자리·부유 폭·안내 문구 여백을 확보한다.
- 펼친 메뉴는 기존 회전 링 배치·아이콘·설명·좌우 방향키를 유지한다. 기존 도크 작업 버튼 행에 '메뉴 축소'를 추가한다. 사각 앵커는 제거한다.
- 펼친 메뉴의 예약 높이는 메인/연출 모두 208px, 높이 500px 이하에서는 172px다. 축소 버튼은 별도 하단 행을 만들지 않는다. 좁은 화면에서 작업 버튼이 넘치면 해당 행 안에서 가로 스크롤한다.

## 상태와 동작

| 사건 | 결과 |
|---|---|
| 최초 메인 진입·새로고침 | 오른쪽 하단의 접힌 구체로 시작 |
| 메인/연출에서 '메뉴 축소' | 설정 패널을 닫고 링 → 오른쪽 하단 구체 전환 |
| 구체 클릭, Enter, Space | 구체 → 링 전환; 장면·재생 시간은 변경하지 않음 |
| 구체를 마우스/손가락으로 밀고 놓기 | 위치 이동 후 그 자리에서 부유; 클릭으로 처리하거나 메뉴를 펼치지 않음 |
| 링의 정면 메뉴 실행 | 기존 장면 실행 후 구체로 자동 축소 |
| 링의 비정면 메뉴 클릭/드래그/방향키 | 기존 링 정렬만 수행; 자동 축소하지 않음 |
| 좌우 정보 카드 또는 음성 명령으로 장면 실행 | 기존 실행 동작을 유지하고 메뉴는 구체로 축소 |
| 도크의 '메인 메뉴'로 복귀 | 메인 화면 및 링 메뉴 펼침 |
| 설정 열린 상태에서 Escape | 설정만 닫고 설정 버튼으로 초점 복귀 |
| 설정 닫힌 링에 초점이 있을 때 Escape | 메인/연출 모두 구체로 축소 |

`preview`와 메뉴 펼침 상태를 분리한다. 현재 `preview || sceneMenuOpen`이라는 강제 펼침 조건은 제거한다. 메인 복귀를 유발하는 카메라 preview 진입 경로도 링을 펼치되, 메뉴 축소 자체는 카메라·음성 연결·선택 장면·재생 여부에 영향을 주지 않는다. 상태는 이번 세션에만 유지하며 저장소에 영구 기록하지 않는다.

## 전환 연출

전환은 약 600~700ms다. 축소 시 링의 메뉴 조각들이 오른쪽 하단 구체 위치로 모이고 깊이 방향으로 감긴다. 펼칠 때는 구체의 현재 위치에서 퍼져 기존 링 위치로 돌아간다. 단순히 두 완성 화면을 페이드 교체하는 것으로 끝내지 않는다.

같은 chapter ID를 가진 시각 조각의 링 좌표와 구체 좌표를 대응시키는 전환 계층을 둔다. 두 상태에서 그림이 잠깐 공존하더라도 의미 있는 버튼은 현재 목표 상태의 한 벌만 활성화한다. 메뉴 라벨·설명·방향키는 전환 중 사라지거나 등장하되 읽을 수 없는 작은 글자로 구체에 남기지 않는다. 부유/연속 회전과 펼침 변환은 서로 다른 래퍼에서 합성해 transform 덮어쓰기를 방지한다.

빠른 반복 입력은 마지막 요청 상태로 수렴하고 중복 실행이나 초점 유실을 만들지 않는다. 크기 변경 시 현재 목표 상태의 좌표를 다시 계산한다. 전환 도중 장면 실행·메인 복귀가 발생해도 그 사건의 목표 상태가 우선한다. `transitionend` 하나에 상태 완료를 의존하지 않는다.

## 접근성과 공간 확보

- 구체 전체를 하나의 네이티브 버튼으로 만든다. 최소 44×44px 터치 영역, `aria-label="하단 메뉴 펼치기"`, `aria-expanded`, `aria-controls`를 제공한다. 표면 아이콘은 장식이며 개별 버튼으로 중첩하지 않는다.
- 축소 조작 후 구체 버튼으로 초점을 이동한다. 펼치면 링의 현재 정면 메뉴로 이동한다. 초기 페이지 렌더링에서는 입력창 등 사용자의 초점을 빼앗지 않는다.
- 명시적인 축소 버튼/도크 Escape는 구체로 초점을 이동한다. 음성 명령 등 자동 축소는 기존 초점이 숨겨질 도크 안에 있었을 때만 구체로 이동하고, 도크 밖에 남아 있는 입력 요소의 초점은 유지한다. 장면 전환으로 초점 요소가 제거된 경우에도 구체를 키보드 접근 가능한 복귀 지점으로 제공한다.
- 닫힌 링 및 설정은 `inert`/`aria-hidden` 처리하여 키보드와 스크린리더에서 제외한다. 펼친 상태의 구체 시각 복제도 장식 처리하고 초점 대상에서 제외한다.
- 구체 클릭/드래그 이벤트는 아래 연출 화면으로 전달되지 않아야 한다. 구체 밖 영역은 기존 화면을 조작할 수 있게 유지한다. 전면 구체는 콘텐츠 위에 겹칠 수 있으며 사용자가 치워 둘 수 있다. 안내 문구와 부유 폭을 포함해 화면 바깥으로 나가지 않도록 제한한다.
- `prefers-reduced-motion: reduce`에서는 부유와 회전을 정지하고 전환을 즉시 처리한다. 화면이 비활성 상태일 때 불필요한 애니메이션을 멈춘다.
- 변경된 `--film-dock-space`를 메인 영역, Canvas 뷰포트, 온습도/설비 터치 좌표가 동일하게 사용한다. 기존 `useFilmPlayback`의 메뉴 속성 관찰과 좌표 역변환을 유지한다.

## 책임 분리와 영향 경로

- `SignalFilm.tsx`: 메인/연출과 독립적인 메뉴 상태, 진입·복귀 연결만 담당한다. 기존 데이터 주입·음성·카메라 경로를 보존한다.
- `FilmDock.tsx`: 펼침/축소 명령, 설정 닫기, Escape와 초점 관리. 구체 geometry를 직접 쌓지 않는다.
- 새 구체 컴포넌트와 CSS 모듈: 기존 메뉴 아이콘을 배치하고 부유·회전·전환 시각 계층을 담당한다.
- 새 순수 geometry 모듈: 구체 면 위치·방향 및 링↔구체 조각 대응 정보를 제공한다. 메뉴 개수와 화면 크기를 입력받는다.
- `FilmChapterMenu.tsx` 및 기존 링 geometry: 선택·드래그·키보드 의미를 유지하며 전환에 필요한 조각 배치 정보를 공유한다.
- `filmDock.module.css` / `film.module.css`: 사각 앵커 제거, 반응형 예약 높이, 펼침/축소 상태 스타일.
- `DESIGN.md`: 구현 시 메인 강제 펼침·사각 앵커·기존 예약 높이 규칙을 새 규칙으로 갱신한다.

## 검증과 완료 조건

1. 순수 geometry 테스트: 모든 메뉴 ID가 정확히 한 번 대응되고 좌표가 유한하며, 면 중심이 지정 구 표면에 있고 이웃 면 크기에 여유가 있다. 입력 개수 변경에도 누락/중복/0 나눗셈이 없어야 한다.
2. UI 회귀 테스트: 메인에서도 축소 가능, 구체는 하나의 펼침 버튼, 설정 닫기 순서, 정면 선택 후 축소, 비정면 정렬만 수행, 메인 복귀 시 펼침, 닫힌 상태의 inert 및 aria 속성.
3. 실제 브라우저 검증: 데스크톱과 모바일(390×844 기준), 짧은 가로 화면에서 조각 틈·깊이·부유·전환 중간 상태·터치·초점·스크롤 넘침을 확인한다. 메뉴 3회 반복 전환 후 상태가 안정적인지 확인한다.
4. 열린/닫힌 상태에서 중앙 콘텐츠 예약 공간과 온습도 카드 터치 좌표가 맞는지 확인한다. 구체 클릭으로 재생을 일시정지하거나 실제 음성/카메라를 시작하지 않는다.
5. 모션 줄이기 환경의 정지 구체와 즉시 전환을 확인한다.
6. `npm run typecheck`, `npm run test:unit`, `npm run lint`, `npm run build`로 검증한다. 다른 작업에서 발생한 오류는 별도로 보고하고 덮어쓰지 않는다. 브라우저 검증이 막히면 정확한 미검증 항목을 남긴다.

## 제외 범위

구체 표면에서 직접 장면 실행, 구체 드래그에 의한 방향 회전, 새 메뉴나 아이콘 제작, 실제 축구공 메시 모델링, WebGL/Three.js 신규 의존성, 서버/API 변경은 하지 않는다. 구체의 화면 내 위치 이동은 사용자 추가 요청으로 범위에 포함한다. 기존 개발 서버와 3000 포트를 유지하며 무단 재시작·포트 변경을 하지 않는다.
