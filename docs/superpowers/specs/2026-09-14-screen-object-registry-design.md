# Screen Object Registry Design

## Goal

화면에서 운영자가 조작할 수 있는 객체가 자신의 상태와 허용 메서드를 등록하고, 클릭·텍스트·음성이 같은 실행 경로를 사용하게 한다.

## Design

- `screenObjectRegistry.ts`는 객체 ID, 설명, 메서드 설명, 인자 스키마, 실행 함수, 상태 조회 함수를 관리한다. 동일 ID의 동시 등록은 오류로 거부하고 직접 호출도 인자 스키마를 통과해야 실행한다.
- React 화면 객체는 `ScreenObjectProvider`와 `useScreenObject`로 마운트 중에 자신의 메서드를 등록한다.
- 기존 `control_screen` 입력 스키마, `ScreenResult`와 상태 key, `describeScreenState` 출력, 배치 전체 선검증, 실행 후 상태 확인을 유지한다. `useScreenCommands`가 기존 key를 객체 ID와 메서드 호출로 변환해 호환성을 보장하며 객체 카탈로그를 기존 상태 응답에 섞지 않는다.
- 좌우 스트림, 카드 확대, 신호 감지기, 중앙 리액터처럼 이전에 DOM selector로 실행하던 객체부터 자체 등록 방식으로 전환한다.
- 재생기·카메라·CCTV·3D 설비·온습도 컨트롤러도 객체 어댑터로 등록해 중앙 switch를 줄인다. 화면 클릭 핸들러와 등록 메서드는 객체 내부의 동일 액션 함수를 호출해 상태 변경 규칙을 공유한다.
- API 키, 비밀번호, 로그아웃 같은 민감하거나 파괴적인 기능은 등록 대상에서 제외한다.

## Execution and errors

등록되지 않았거나 현재 화면에서 사용할 수 없는 객체 메서드, 스키마에 맞지 않는 인자는 실패 결과를 반환한다. 메서드 실행 뒤 기존 상태 스냅샷을 읽어 실제 반영 여부를 확인한다. 객체 메서드 예외는 공통 실패 결과로 바꾼다. DOM selector 제거 범위는 명령 실행과 상태 조회 경로이며 레이아웃 측정, 포커스, 시각 효과 내부 selector는 유지한다.

## Verification

레지스트리 등록·해제·중복 거부·인자 검증·호출·카탈로그 테스트, 기존 screen command 실행 테스트, 명령 실행 중 DOM query 미사용 테스트, 타입 검사를 실행한다. 개발 서버의 텍스트 명령으로 카드 확대와 스트림 정지를 확인한다.
